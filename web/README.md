# NCBO Member Hub

The public floor of the member hub: standings, events, the club directory and map,
and the reference material behind them. Static Astro, TypeScript strict, zod
validation at build time.

**No external accounts, keys or services.** After `npm install` everything runs
offline: fonts are self-hosted, the map geometry is vendored, the data is
committed, and no page makes a network request at runtime.

## Run it

```sh
cd web
npm install
npm run dev          # http://localhost:4321
```

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Dev server |
| `npm run build` | Static build to `dist/` (runs `build:templates` first) |
| `npm run check` | `astro check` + `tsc --noEmit` |
| `npm test` | Vitest — scoring, ICS, auth guard, privacy defaults |
| `npm run check:content` | Fails on a content-policy violation |
| `npm run check:contrast` | Fails on a WCAG 2.1 AA contrast failure |
| `npm run verify` | All four of the above. **This is the pre-commit check.** |
| `npm run build:templates` | Regenerates club template PDFs from `data/templates/` |
| `npm run fetch:enrollment` | Downloads IPEDS enrollment. Needs network. See `docs/DEFERRED.md` |

## Where things live

```
data/                     committed organisation data, outside the app
  clubs/*.json            the six founding chapters
  events/                 empty — nothing is scheduled
  conferences/            empty — no conference structure exists
  templates/*.md          club template sources
  samples/                sample data, dev-only, never in a production build
  enrollment.json         generated by scripts/fetch-enrollment.ts; currently empty
scripts/fetch-enrollment.ts
web/src/
  lib/scoring/            the standings maths, unit-tested, framework-free
  lib/schemas.ts          zod schemas — the build gate
  lib/auth/               types, roles, route guard, dev-only provider
  content/resources/      the Markdown reference pages
  components/ pages/ layouts/ styles/
```

## Two things to know before changing anything

**1. Sample data can never ship.** `data/samples/` loads only under
`NCBO_DEMO_DATA=1` on the dev server, renders under a non-dismissible banner, and
**throws** during a production build. No number in a production build may be
presentable as a real standing.

```sh
NCBO_DEMO_DATA=1 npm run dev      # sample standings, banner on
NCBO_DEMO_DATA=1 npm run build    # fails, deliberately
```

**2. Facts need sources.** Every external claim carries a citation with an access
date, and the schema enforces the shape. If you cannot verify something, cut it
and say so on the page — see the "what we could not verify" section on
`/resources/competing` for the pattern. `docs/SOURCES.md` lists everything cited.

Read `docs/CONTENT-POLICY.md` before editing anything under
`src/content/resources/`. Some of those rules are enforced by
`npm run check:content`; all of them matter.

## Relationship to the rest of the repo
